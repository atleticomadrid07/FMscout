# ERRORS.md

Approaches that failed, what fixed them, and what to remember. Check before suggesting a similar approach.

## 2026-11-19 · Editable install ignored in the iCloud Desktop folder
- **Symptom:** `ModuleNotFoundError: scouting` despite `uv sync`; the venv's `.pth` file was flagged hidden.
- **Cause:** iCloud-synced folders mark files hidden, and Python skips hidden `.pth` files.
- **Fix:** moved the repo to `~/dev/FMscout`. **Remember:** never put Python projects in iCloud-synced folders.

## 2026-11-19 · zsh breaks pasted commands
- **Symptom:** "number expected" / parse errors.
- **Cause:** `#` comments in pasted multi-line blocks, and `<id>` placeholders read as redirection.
- **Remember:** give clean, copy-pasteable commands with real values; put explanations outside the code block.

## 2026-11-19 · Assumed the documented `/players` shape
- **Symptom:** the analyzer found no stat entries.
- **Cause:** real entries are `{key, stat: {type, value, total}}` keyed by display label, not the documented shape; `/players` is also a bare list while other endpoints wrap theirs.
- **Remember:** verify every response shape against a real sample before writing a parser (PITCHAPI_NOTES).

## 2026-11-20 · Files missing from the user's working copy
- **Symptom:** missing modules (cache.py, client.py) after unzipping a later slice.
- **Fix:** `unzip -n restore_through_1b.zip`. **Remember:** when a slice zip contains only changed files, confirm earlier slices are fully in place; check `git status` after unzipping.

## 2026-11-20 · Alembic migration failed on a database with data
- **Symptom:** `FOREIGN KEY constraint failed` on `DROP TABLE metric` during `alembic upgrade head`.
- **Cause:** `server_default=false()` in the model autogenerated as `sa.text("0")`. For a SQL-expression default, Alembic's SQLite batch mode rebuilds the whole table (copy, drop, rename), and the drop fails once `stat_value` rows reference it. Tests only ran migrations on empty databases, so they missed it. The failed run left an `_alembic_tmp_metric` table behind.
- **Fix:** `server_default="0"` (plain string) in the model and migration, which uses `ALTER TABLE ADD COLUMN`; dropped the leftover temp table, re-ran the upgrade.
- **Remember:** string server defaults only (D-013). Test migrations against a database that already has data. Downgrades that drop columns on SQLite will hit the same problem.

## 2026-11-20 · Profile step lost its work when stopped
- **Symptom:** after the online season crawl, only 53 of 537 profiles were cached and none applied.
- **Cause:** the profile step ran as one transaction with no progress output, so it looked frozen; stopping it rolled everything back.
- **Fix:** commit every 25 players, print progress, handle Ctrl-C, skip malformed profiles.
- **Remember:** any long sync step needs chunked commits, visible progress and Ctrl-C handling, not just the main loop.

## 2026-11-21 · A paste file sent as `.py` ended up in `migrations/versions/`
- **Symptom:** every test that asks Alembic for the head revision failed at collection: "Could not determine revision id from filename migration_2d3_dm_peer_role.py".
- **Cause:** the migration paste text was delivered as a `.py` file, and a copy landed in `migrations/versions/`. Alembic loads every `.py` there as a revision.
- **Fix:** moved the copy out (`mv … ~/Downloads/migration_2d3_copy.py`).
- **Remember:** send migration paste text as `.txt`, or apply it with a one-shot command that edits the generated file (as done for 2d-3). Also: Alembic's ruff post-write hook strips the unused `sa`/`op` imports from an empty revision, so pasted bodies must add them back.

## 2026-11-21 · Patched constants didn't reach `classify`
- **Symptom:** a test that monkeypatched the 6/8 cut saw no change.
- **Cause:** the cut was a default argument, bound when the function was defined.
- **Fix and remember:** defaults that tests (or reports) may change are `None` and read from the module at call time; the CLI imports `metrics.depth` as a module.

## 2026-11-22 · Read-only SQLite URL through `make_engine` (Claude's workspace)
- **Symptom:** a folder literally named `file:` appeared next to the database.
- **Cause:** `make_engine` creates the database's parent folder, and with the URI form (`sqlite:///file:/abs/path?mode=ro&uri=true`) it took `file:` as part of the path.
- **Fix:** the API's `read_only_engine` uses plain `create_engine` (nothing to create for a read-only database).
- **Remember:** helpers that prepare a path for writing don't fit read-only URIs.

## 2026-11-22 · Test layout broke mypy (Claude's workspace)
- **Symptom:** mypy reported a duplicate module / "found twice" after adding API tests.
- **Cause:** tests run with `--import-mode=importlib` and no `__init__.py`, so a second `conftest.py` (in `tests/unit/api/`) and one test module importing another both put the same module name on mypy's path twice.
- **Fix:** the `api_db` fixture lives in the root `tests/conftest.py`; small helpers (`cli()`, `error()`, the `client` fixture) are repeated inline in each API test file.
- **Remember:** one `conftest.py`, and test modules never import each other.
